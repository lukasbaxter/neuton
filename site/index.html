neuton

A Minecraft: Java Edition client written from scratch in Rust. No Mojang jar at runtime. Multiplayer only.

Why

Every fast Minecraft client is a mod. Sodium, Iris and the rest are excellent, but they are patches over a codebase that loads a thousand JSON files before it draws anything, and they inherit its floor.

neuton has no floor to inherit. It speaks the 26.2 protocol, decodes the world and draws it. Dropping single player removes world generation, the save format and the integrated server. That is most of the game, and none of it renders a frame.

Rust

Chosen for what it removes from the hot path, not for the language politics.

no gc
Frame time is the product. A collector pause is a dropped frame with no stack trace attached to it.
reads borrow
A string off the wire is a &str into the receive buffer. Decoding a packet allocates nothing.
tables are static
32,366 block states compile into .rodata. State ID to block is one bounds-checked index. No hashing, no parsing, no init.
sections stay packed
Palettes unpack lazily into a reused scratch buffer. At render distance 16 that is the difference between kilobytes and hundreds of megabytes resident.
blocking sockets
One connection does not need a runtime. A dedicated thread parked on read beats a scheduler wakeup, and tokio never enters the binary.
eight dependencies
Client core: flate2 aes rsa sha1 rand serde serde_json ureq. No protocol crate, no engine, no framework. The renderer adds wgpu on top of that and nothing else.
1.8 MB
Release binary. Fat LTO, one codegen unit, panic = "abort", symbols stripped.

Startup

Most of what the game does before the title screen produces the same answer every launch. neuton does it at build time and ships the result.

workvanillaneuton
registries, block statesparsed from JSONstatic arrays
packet idsbuilt by reflectionconst i32
block modelsparsed, then bakedpre-baked geometry
texture atlasstitched every launchpre-stitched, compressed
shaderscompiled every launchcached pipelines

The tables come from the game itself. 26.x jars ship unobfuscated with their own data generator, so neuton-datagen runs it against a real installation and emits Rust source. Packet IDs and block state IDs cannot drift from the version they target.

Download

windows x64macos arm64linux x64
sign-in pending approval Third-party clients need their Microsoft application reviewed by Mojang before anyone can sign in. That review has not come back. Everything up to it works: Microsoft, Xbox Live and XSTS all issue tokens, the final call to Minecraft services is refused.

Accounts

Sign-in goes through Microsoft. The result stays on your machine.

flow
OAuth device code. neuton prints a code, you approve it on Microsoft's site.
password
Never entered into neuton, never transmitted through it, never stored.
at rest
One file, mode 0600, written atomically. Multiple accounts, one active.
network
Microsoft, Xbox Live, Mojang, and the server you join. Nothing else.
telemetry
None. No analytics, no crash reporting, no account on our side. There is no server on our side.
revoking
neuton logout deletes the file. Microsoft-side at account.live.com/consent/Manage.
